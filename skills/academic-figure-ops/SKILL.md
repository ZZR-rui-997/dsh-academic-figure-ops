# academic-figure-ops — 学术插图的“怎么画、怎么验”

这个 skill 只干一件事：**让插图在纸面上真的看得清**。

它不教通用可视化理论，也不提供“27 种图型大全”。它固化的是反复踩过的坑：
**脚本里写着 10.5 pt，插进版面后只有 5.9 pt**——屏幕上根本看不出来，印出来才发现。

它唯一的前提假设是：你的图最终会被**缩放到某一条固定的正文宽度**里排版。这条宽度就是“版心宽”，下面所有公式都从它出发——而它是**参数，不是常数**。

## 零、怎么用（安装、依赖、自检）

**装法 A（个人 skill 目录）**：把整个 `academic-figure-ops/` 目录放进 `~/.dsh/skills/`，保持 `scripts/`、`references/`、`assets/` 的相对结构不变（脚本按相对位置找同目录的 `references/`）。会话会自动发现它。

**装法 B（bundle）**：安装 `dsh-academic-figure-ops` bundle，一条命令装进当前 profile（版本要求以 bundle manifest 为准）。

**依赖**：Python 3.10+（脚本用了 `str | Path`、`list[str]` 这类 3.10 语法）+ `numpy` + `matplotlib` + `Pillow`。Pillow 只在验收器与 `saved_width_in()` 里用得上，但缺了 `check_figure.py` 会直接 exit 3，所以别省。建议装在独立 venv 里，别用裸系统 python（最常见的报错是 `ModuleNotFoundError: No module named 'numpy'`）。

**可选依赖**：真三维场景另需 `pyvista`（本文实测 0.49.3，VTK 9.7.1 底座）。它只在 `references/cfd-3d-render.md` 这条渲染路线上用到，不装不影响其余功能，也不进 `requires`。

**第一次用先自检**：

```bash
python scripts/figstyle.py      # 内置 _selftest()，逐条核反算恒等式 / use_size / fit_and_save 契约 / panel 字重
```

末行打印“结论：全部通过”并返回 0；任何一条 `[FAIL]` 都说明这份副本被改坏了，先修脚本再画图。

**本 skill 不含任何厂商软件、不含第三方图库、不附带任何商业求解器或后处理器。** CFD 部分是“结果已经在手之后怎么画”的规程；案例库（`assets/case-gallery/`）的 19 个配方全部是合成数据重画的，可独立运行、可自由分发。

## 何时加载

出现下列任一情况，先读本 skill 再动手：

- 画新的数据图（折线、柱、箱线、散点、云图）或示意图；
- 调字号、改 `figsize`、有人反馈“图里的字太小了”；
- 判断某张已落盘的图**是否达标**（`check_figure.py`）；
- 一批图风格不齐（字体、dpi、线宽、配色各写各的），要拉齐；
- 写图注、排分幅标号 (a)(b)(c)；
- 投稿/送审前要按目标期刊或学校模板查分辨率与矢量格式；
- 想把“别人的好图”拆成可复用的知识（案例卡）。

不适用：交互式仪表盘、数据清洗、统计检验本身（那是别的工具的事）。

## 一、核心概念：印刷字号 ≠ 脚本字号

### 1. 版心宽是参数，先量出来

“版心宽”= 排版时正文实际占用的那条宽度（不含左右页边距）。它由页面尺寸和页边距决定，**跟你用什么画图工具毫无关系**。

1. 打开你的模板或正文文件，量一行正文的可用宽度（cm）。
2. 常见示例：A4 纵向 + 左右各 3.17 cm 页边距 → 正文宽 **14.65 cm**（= 5.7677 in）。**这只是示例值**：双栏半栏可能是 7.5 cm，A4 单栏宽边距可能是 16 cm，报告页可能是 12 cm。量你自己的。
3. 把这个数设进两个地方，**必须同值**：
   - `figstyle.py`：首选 `set_text_width_cm(<cm>)`（它会一并重算 `K/FS/FT`，且若已 `apply_style()` 过就顺手刷新 rcParams）；等价写法是给模块常量 `TEXT_WIDTH_CM` 赋值后再调一次 `apply_style()`。`TEXT_WIDTH_IN` 由它 `/ 2.54` 派生。**只走一个入口**：别一手改模块变量、另一手忘了改封装。
   - 验收器 `check_figure.py --text-width-cm <cm>`（缺省 14.65，即上面的示例值）。
4. 换成你自己的值之后，下面整条反算链**照样成立**——链里没有任何一步依赖 14.65 这个具体数字。

> 只改一处是最隐蔽的错：`figstyle` 按 16 cm 放大字号，验收器仍按 14.65 cm 反算，整批判定会整体偏大 9%，全判 FAIL 而你还以为图坏了。

### 2. 反算恒等式（整个 skill 的地基）

```
印刷字号pt = 图内设定pt × 版心宽cm ÷ 落盘图宽cm
             └──────┘   └──────┘   └────────┘
              rcParams    你的正文宽   实际落盘的图宽
```

换算成英寸时（代码里用英寸计算）：

```
落盘图宽cm = 像素宽 ÷ dpi × 2.54        # 注意：是落盘图宽，不是 figsize 宽
印刷字号pt = 设定pt × TEXT_WIDTH_IN ÷ (像素宽 ÷ dpi)
有效分辨率dpi = 像素宽 ÷ TEXT_WIDTH_IN   # “缩进版心后每英寸还剩多少像素”
```

**为什么必须有这一步**：matplotlib 的 `font.size=10.5` 是“以画布英寸为基准的相对量”。同一段 10.5 pt 文字，放在“画布宽 = 版心宽对应的英寸数”的画布上（示例：14.65 cm 版心 → 5.7677 in 画布），缩进版心时**正好还是 10.5 pt**；放在 10 in 宽的画布上，缩进同一版心时**被压成 6.06 pt**（10.5 × 5.7677 ÷ 10）。纸张不会因为你的画布大就给你更宽的位置——它永远只有你量出来的那条版心宽。

所以：**画布越宽，字号必须跟着放大，否则印出来越小。**

“10.5 pt”是示例目标值，也是多数期刊对图内正文级文字的常见基线（图内最小字号常见要求 7–8 pt，投稿前以目标期刊 Guide for Authors 为准）。你要改成 12 pt，就改 `TARGET_LABEL_PT`，其余链条不动。

### 3. 两种写法，同一个 PNG，无法从文件反推

实践中常见两套写法并存。落盘 PNG 长得一模一样，检查器**无法从像素反推是哪一套**，所以必须由使用者显式声明：

| | 口径①：`use_size` 约定 | 口径②：固定字号约定 |
|---|---|---|
| 代码 | `figstyle.use_size(W)` + `figsize=(W, ...)` | `rcParams['font.size']=10.5`，不调 `use_size` |
| 实际设定 pt | `10.5 × W ÷ 版心宽in`（示例 W=13 → 23.67） | `10.5` |
| 印刷 pt | `10.5 × W ÷ 落盘宽in` | `10.5 × 版心宽in ÷ 落盘宽in` |
| 谁在用 | 大画布 + 自动放大字号的那批图（新图推荐走这条） | 固定字号、脚本批产的图（多为历史遗留） |
| 检查参数 | `--canvas-w W` | `--fs 10.5` |

**把口径①当成②算会怎样**：一张 13 in 画布、`use_size(13)` 的图，设定 pt 其实是 23.67，印刷态 10.41 pt（达标）；若按 10.5 去算就得 4.62 pt（判 FAIL）。这就是“一批自信的错误 FAIL”的来源。

所以 `check_figure.py` 在两个参数都不给时**直接 exit 2 拒绝判定**，绝不用默认值猜。

### 4. 为什么“大画布 + use_size”是恒等式，不是魔法

`use_size(W)` 做的就是 `K = W ÷ 版心宽in`，然后把所有字号乘 K。这样“画布宽 W、缩放回版心宽”时，字号恰好回到目标 pt（示例 10.5）。**是恒等式，不是魔法。**

代价：画布越宽，图内字号越大，坐标区被吃掉越多。宽画布配小高度时标签必挤——**优先改布局（加高、减分幅、缩边距），不要硬压字号**，否则 ink 密度下不去，图看着“糊”。

`figstyle` 模块级还有一组 `K / FS / FT`（按 13.0 in 预先算好的默认值）。**只改 `figsize` 不调 `use_size` 是最常见的错**：画布 16 in 却仍按 13 in 放大字号，印刷字号会掉 19%。

## 二、三个动作

### 1. 画一张新图

```python
import sys
sys.path.insert(0, "<skill 根目录>/scripts")

import matplotlib.pyplot as plt      # ← 少这一行会 NameError: name 'plt' is not defined
import figstyle as fs

# 画布宽取“版心宽英寸数”的 2–2.5 倍（示例版心 5.7677 in → 12–14.5 in）
fs.use_size(13)                      # ← use_size 实参必须 == figsize 宽；内部已调 apply_style()
fig, axes = plt.subplots(1, 2, figsize=(13, 5.6), layout="constrained")
...
fs.panel(axes[0], "(a)")             # 分幅标号写在坐标区下面，不写进标题
fig.savefig("out.png", bbox_inches="tight", dpi=300)
# 示例：落盘 3900 px 宽 → 缩进 14.65 cm 版心后：字号 10.4 pt + 有效 676 dpi，两项同时达标
```

`savefig` 的两件事别省：`bbox_inches="tight"`（否则空白边距吃掉版心比例）与 `dpi=300`（`savefig.dpi` 已在 `apply_style()` 里接到 `DEFAULT_DPI`，但显式写出来更不容易被别处的 rcParams 覆盖）。

#### 两个必须知道的排版坑（都是被实图否出来的）

> 下面这块**承接上一个示例**（`ax`/`fig` 已建好，`plt`、`fs` 已 import），不是独立可跑的代码。

```python
fs.fix_corner_labels(ax)   # 左下角 y 最小值的 "0.00" 与 x 最小值的 "0.0" 会叠在一起
fs.panel(ax, "(a)")        # 必须在 set_xlabel 之后、savefig 之前调用
```

- **角部重叠**：y 轴最小值标签向上留白、x 轴最小值标签向左留白，两者都画在角上那一小块区域，`constrained`/`tight` 都不管。`fix_corner_labels` 把 y 轴极值标签改成“只向内长”（最小值 `va="bottom"`、最大值 `va="top"`），不改刻度值。
- **标号位置**：`panel()` 会先 `fig.canvas.draw()` **实测** x 轴名与刻度数字占到哪里，再把标号放在其下 6 pt。所以它必须在 `set_xlabel`/`set_title` 都调用完、紧接 `savefig` 之前调用。按坐标区高度比例（`dy=-0.28`）或按固定 32 pt 的两种旧做法都被实图否掉过：前者在 13×8.1 in 六分幅里偏出 21 mm，后者压住 `x / mm`。

### ⚠ 不要为了省事把画布改成“版心宽英寸数”

这是一个反直觉但已实测的结论：

| 配方 | 印刷字号 | 有效分辨率（缩进示例版心 14.65 cm 后） |
|---|---|---|
| `figsize` 13 in @300 dpi + `use_size(13)` | 10.4 pt ✅ | **676 dpi** ✅（线条图常要 ≥600） |
| `figsize` 5.77 in @300 dpi + `use_size(5.77)` | 10.5 pt ✅ | **300 dpi** ❌（只够照片级） |
| `figsize` 5.77 in @600 dpi + `use_size(5.77)` | 10.5 pt ✅ | 600 dpi ✅（但文件 4 倍大） |

**有效分辨率 = 落盘像素宽 ÷ 版心宽(in)**，只取决于“像素宽”，与 PNG 里标的 dpi 参数无关。改成 5.77 in 虽然字号天然达标，但像素宽只剩 1730 px，分辨率掉到 300 dpi。

**所以“大画布 + use_size”不是绕远路，而是一举两得**：画布宽 12–14.5 in 既给字号留出放大余地，又让像素宽足够。

### `bbox_inches='tight'` 的陷阱（反算为什么必须用落盘宽）

`tight` 会在保存时**重新裁一次画布**，落盘宽不等于 `figsize` 宽（裁切比 α 常见 0.80–1.00）。于是：

- 反算的分母永远是**落盘宽**（`像素宽 ÷ dpi`），不是 `figsize` 宽；用 `figsize` 算出来的印刷字号会系统性偏小。
- 同一份代码改了内容（图例变长、标题变宽）就会改变 α，落盘宽跟着变，字号也变——**同样的 `figsize` 不等于同样的成图比例**。
- 这也是 `fit_and_save()` 存在的原因：它实测落盘宽再补偿，而不是假设落盘宽=figsize 宽。

### 要“可编辑的矢量图”怎么办

matplotlib 本来就支持 `savefig("x.pdf") / .svg / .eps`，**线条天然可编辑**；但文字默认不可编辑，必须设三条 rcParams：`pdf.fonttype=42`、`svg.fonttype="none"`（EPS 用 `ps.fonttype=42`，注意 EPS 不支持半透明，云图慎用）。42 之后 PDF 里的 Times/思源宋体会以 FontFile2（TrueType）嵌入，SVG 保留 `<text>`，在 Illustrator/Word 里能选中改字。

**`fit_and_save` 只能出位图**（它用 PIL 量落盘宽，PDF 读不了）。要矢量且要收敛：走两步法——先出一张 PNG 当探针拿到收敛的 `fit_scale`，再用同 scale 直接 `fig.savefig("x.pdf")`。完整说明见 `references/resolution-and-format.md` 的“矢量图要可编辑”一节。

### 2. 验收一张已落盘的图：三类判据

一张图要同时过三关，缺一不可：

1. **落盘像素宽**（px）：分辨率的上限分子；`saved_width_in()` 就是拿它除以 dpi。
2. **落盘宽**（in）= `像素宽 ÷ dpi`：反算的分母。dpi 的取法有顺序：优先读 PNG 的 pHYs 块，其次 `--dpi` 覆盖，最后退 300——**退 300 是兜底不是实测**，若结果里的 dpi 恰好是 300 而你没声明过 300，回头查原图的 dpi 声明。
3. **印刷字号**（pt）与**有效分辨率**（dpi）：`印刷pt = 设定pt × 版心宽in ÷ 落盘宽in`；`有效dpi = 像素宽 ÷ 版心宽in`。两者**互相独立**：字号达标但有效分辨率不够，仍判 FAIL，修复建议会分开给。

```bash
# 口径②（固定字号那批）
python check_figure.py --fs 10.5 <目录或png>

# 口径①（use_size 那批；每张画布宽不同时用清单）
python check_figure.py --pair canvas_map.txt
#   canvas_map.txt 每行：13.0,./out/fig_a.png   （空行与 # 注释跳过）

# 加分辨率判据（投稿/送审常用；线条图期刊常要 600，照片 300）
python check_figure.py --fs 10.5 --min-eff-dpi 600 <目录>

# 换成你自己的版心宽（必须与 figstyle 的 TEXT_WIDTH_CM 同值）
python check_figure.py --fs 10.5 --text-width-cm 16.0 <目录>
```

其他开关：`--tick-pt`（刻度判据，默认 9.5）、`--tol`（容许偏差，默认 0.05 即 ±5%）、`--json`（结构化输出，便于批量汇总）、`--quiet`（只看退出码）。

退出码契约：`0` 全达标 / `1` 有不达标 / `2` 未执行（没声明口径、没给路径、读失败、`--pair` 与 `--canvas-w` 混用）/ `3` 缺 Pillow。**`2` 和 `3` 都不能当成通过**——把“未执行”当“通过”是流水线上最常见的假绿。

`fit_and_save()` 收敛后复验时，用返回的 `set_pt` 走口径②，或用它返回的 `effective_canvas_w_in` 走口径①；**不要用 `--canvas-w 13.0`**——那假定 `use_size(13.0)`，而实际用的是补偿过的比例。

### 3. 自动收敛（`fit_and_save`）

不想手算画布宽，用 `fit_and_save`：它落盘 → 量落盘宽 → **只调字号补偿** → 再落盘，迭代到 ±2% 内（画布宽恒定不变，这是它和旧版的关键区别）。

**⚠ 回调函数必须收一个参数**（这是最容易照抄错的地方）：

```python
import sys
sys.path.insert(0, "<skill 根目录>/scripts")

import matplotlib.pyplot as plt      # ← 本块自包含，两行 import 都要
import figstyle as fs

def make_fig(w):                       # ← 必须收 w（画布宽，in）
    fig, ax = plt.subplots(figsize=(w, w * 0.43))
    fs.use_size(w)                     # ← 必须按 w 设定字号；不调会 ValueError（契约校验）
    ax.plot([0, 1], [0, 1])
    ax.set_xlabel("x / mm")
    return fig

res = fs.fit_and_save(make_fig, "out.png", canvas_w_in=13.0, dpi=300)
# 返回 dict 共 10 键：converged / path / canvas_w_in / saved_width_in /
#                    set_pt / printed_pt / iterations / fit_scale /
#                    effective_canvas_w_in / history
```

写成 `def make_fig():`（不收参数）会直接崩 `TypeError: make_fig() takes 0 positional arguments but 1 was given`。

**为什么不能靠改画布宽**（旧版真踩过，值得记住）：回调里 `w` 同时进了 `figsize` 和 `use_size(w)`，于是

```
printed = (10.5 · w/版心宽) · 版心宽 / (α · w) = 10.5/α      ← 与 w 无关！
```

`α` 是 tight 裁切比。旧版每轮令 `w ← α·w`，`w` 一路缩到 2.7 in，产出 919×496 px 的废图**还不报错**。正确做法是画布宽不动、只调字号补偿（`_FIT_SCALE`）。

**⚠ `fit_and_save` 也管不了分辨率**：tight 会把画布裁窄（α 常见 0.8–1.0），所以 `canvas_w_in=13` 落盘可能只有 10.7 in ≈ 3209 px，有效分辨率 556 dpi，不到线条图的 600。以示例版心 14.65 cm 实测（dpi=300，1:0.43 单图）：`canvas_w_in=13` → 556 dpi、14 → 598（仍不达标）、14.5 → 619 ✅、15 → 640、16 → 682。要 600 以上就给 **≥14.5**。`converged` 只表示**字号**达标，分辨率是独立的另一个判据，不要只看字号过了就算完。

## 三、硬参数速查（唯一权威表在 `references/hard-params.md`）

| 项 | 值 |
|---|---|
| 版心宽 | **你的正文宽度（cm）**；示例 14.65 cm = 5.7677 in（A4 + 左右 3.17 cm 页边距） |
| 轴标签 / 正文图内字号 | 印刷 **10.5 pt**（`TARGET_LABEL_PT`） |
| 刻度字号 | 印刷 **9.5 pt**（`TARGET_TICK_PT`） |
| 落盘 dpi | 300（`DEFAULT_DPI`）；`figure.dpi=120` 只管屏幕预览 |
| 字体栈 | `["Times New Roman", "SimSun"]`（西文在前；缺中文字体就会变方框） |
| 轴线 | 四边纯黑实线，`linewidth = 0.65K` |
| 刻度 | 朝内，top/right 都开；主刻度 `width = 0.65K`、`length = 3.0K`；**次刻度 `width = 0.55K`、`length = 1.7K`** |
| 单位写法 | 斜线 `x / mm`，**不用方括号** `[mm]` |
| 分幅标号 | `(a)(b)(c)` 画在**坐标区下方**，不写进标题，默认粗体（`weight="normal"` 可覆盖） |
| 系列配色 | **Okabe–Ito 五色** `#0072B2 / #E69F00 / #009E73 / #D55E00 / #CC79A7`，禁止用灰度深浅区分系列 |
| 连续场配色 | `INK_SEQ` 单色系 or 发散色标；禁用 `jet` |
| 图例 | 方角、黑边（`frameon=True`、`fancybox=False`）；不放阴影 |
| 图注 | 写在版面里图的**下方**，不进图 |

`K = 画布宽in ÷ 版心宽in`。用 `use_size(W)` 时这些已经自动乘好了——这也是为什么**不要在 `use_size()` 之后再手改 rcParams 字号**，会直接破掉恒等式。

## 四、图型选择：按论证意图，不按“好看”

先问三件事（顺序不能颠倒）：**你要让读者相信什么**（比较？相关？分布？构成？）→ **数据是什么形态**（几组、几指标、样本量 n）→ **有多少版面**（单栏、半栏、整页分幅）。

| 论证意图 | 首选 | 次选 | 别用 |
|---|---|---|---|
| 组间比较（n ≥ 10） | 柱 + 误差棒、箱线 | 小提琴 | 纯均值柱（把分布藏了） |
| 组间比较（n = 3–8） | 柱 + 抖动散点 + 极差 | 配对连线 | 纯均值柱、星号显著性 |
| 相关关系 | 散点 + 拟合 + 置信带 | 边际分布（scatter+hist） | 双 y 轴 |
| 分布形态 | 直方图 / 密度图 | 山脊线 | 饼图 |
| 构成占比 | 堆叠条形 | 环形 | 3D 饼 |
| 趋势变化 | 折线（离散点别硬连成平滑曲线） | 面积图 | 只用一条“最好看”的线 |
| 空间 / 场分布 | 填色云图 + 共享 colorbar | 等值线 | 分幅各自归一化 |
| 多指标综合 | 雷达（≤6 维）、平行坐标 | 环形条形 | 超过 6 维的雷达 |
| 排序 | 降序条形 | 点图 | 按字母序排的条形 |

**n 小怎么办**：别画纯均值柱。柱 = 均值（浅色填充 + 黑描边），误差棒 = 极差或 ±SEM（n 小用极差更诚实），抖动散点 = 真实测点（关键）。显著性标注只在检验真的做过、且检验适用时才加，别为“看起来严谨”加星号。

分幅规矩（子图共享轴范围、只留一个 colorbar、标号位置）、colorbar 规矩、以及“什么时候该换思路而不是换图型”——全部在 `references/chart-selection.md`。

## 五、审丑清单：看到就改（要点）

按严重度分四级，完整条目与改法见 `references/anti-patterns.md`。

**★★★ 一眼掉档（也最容易致命）**

- **字号偏小**：印刷 <10 pt 已显局促，<7 pt 基本不可读。先按本 skill 反算，别靠“我屏幕上看着还行”。
- **分幅比较时轴范围不一致**：读者会跨幅比较，范围不一致等于给出错误对比。
- **云图 colorbar 各自归一化**：同一组图必须共享 `vmin/vmax`，否则颜色不可比。
- **y 轴不从 0 起又不标注**：截断轴必须显式说明，否则夸大差异。
- **用灰度深浅区分系列**：印出来（尤其黑白打印）分不开；用 Okabe–Ito 或形状+线型。
- **内容层面的假象**（最危险）：n=3 画纯均值柱、n=3 标显著性、误差棒不写是什么（SD？SEM？极差？）、平滑曲线硬连离散点、只挑最好看的一条画、图注夸大结论。

**★★ 让人怀疑专业度**

- 中文变方框（字体栈缺中文字体）；单位用方括号；图例压住数据；文字压线且无白底；网格线过密；双 y 轴（除非两量纲真的必须同图）；角上两个刻度标签叠在一起（用 `fix_corner_labels`）；分幅标号悬空或压字（用 `panel`）。

**★ 显得不整齐**

- 同批图字体不一致；dpi 五花八门（150/180/300 混着）；轴线宽不统一；marker 密到糊成一条粗线；图例带圆角/阴影。

**快速自检**：把图缩到版心宽看一眼（示例 14.65 cm ≈ 553 px @96 dpi），字号与元素冲突当场现形。这一步 10 秒，能挡掉上面一半的问题。

## 六、七条硬规矩（吸收自成熟制图工具的方法论）

这七条管的是「这张图能不能被别的工具接手、改稿时会不会做假修复」，是从开源制图
工具 Tavotto 的公开文档里提炼并在本 skill 落地的（它家的数值不进本 skill 的判定）。
细则、四级话术表与口径对表见 `references/tavotto-inspired-rules.md`。

1. **图文件契约**：脚本与产物同目录；产物名是静态可解析的字面量（不来自 argv / 时间戳 / 遍历）；
   无参 `main()`、import 期零副作用；交付矢量 PDF，位图 raster 除外且 ≥300 dpi；随机种子固定；
   禁 `plt.show()`（阻塞无人值守渲染），落盘脚本走 `show_or_save`。
2. **preflight 四级**：to fix / to review / not verifiable / suggestion。**任何一级都不锁交付**，
   但 to-fix 与 not-verifiable 必须写进交付说明，不能「看起来还行就交」。
3. **克制原则**：数据之外的效果（背景色块、指示箭头、「peak here」式文字、高亮/星号装饰）
   一个都不擅自加；确实有助理解就先问要加什么、为什么，点头才画。
4. **多子图四条**：不用 matplotlib 之外的东西拼图（不拼位图、不用 LaTeX subfigure）；
   每个子图的 x/y 轴标题各自标全；不 `sharex/sharey`（要对齐就逐个 `set_xlim/set_ylim`）；
   `set_title` 各归各位，不挤整图左上角。
5. **字重按角色**：figure / title / ticklabel / legend / annotation 一律 normal，
   **只有轴标题 bold**，不整图一刀切。
6. **保留式规范化禁止绕路**：不缩放位图冒充「已改字号」、不整份替换 SVG/PDF、不套全局
   rcParams 主题、不为消除拥挤删曲线/图例项/刻度/文字、不改配色与数据与坐标范围、
   字体缺失就装或换并如实报告。
7. **期刊规范按字段记**：图类条件 / 投稿阶段（修稿 / 录用后 / 生产不可互换）/ 比较符
   （≥ ≤ in not_in）/ 要求强度（must / preferred / permitted）/ 来源原文 / 「未规定 ≠ 未见规定」。

## 七、CFD 后处理云图范式

前提：本 skill **不含求解器模板**，它管“结果已经在手，怎么画成能印的图”。下面的做法来自 Fluent / CFD-Post 这类工具的通用输出流程（导出为场数据后进 matplotlib，或后处理器出图后按本 skill 的版心/字号/分辨率验收）；换软件时机制相同，具体命令与导出格式自己换。

- **相分布 / VOF 云图**：先定色标语义（两相用离散两色或发散色，过渡带显式给 0.1/0.5/0.9 等级线）；`levels` 显式给定，不靠默认；**分幅共享一个 colorbar**（只画一个，范围由全部数据决定），`vmin/vmax` 显式写，禁止每幅各自归一化。
- **速度场 + 流线**：数据先抽稀（每线 400 点左右），否则矢量文件体积爆炸、印刷糊成一团；箭头图看方向、流线看路径，别混用；`streamplot` 的 `density` 与 `broken_streamlines` 要显式设定。
- **压力场**：发散色标以 0（或参考压力）为对称中心（`TwoSlopeNorm`），别用 `jet`。
- **沿程剖面 / 时间曲线**：与数据图完全同口径，走 `figstyle`。
- **参数敏感性**：小多图（grid）比叠 5 条线清楚，每格共享相同轴范围与 colorbar。
- **网格 / 几何示意**：矢量线稿或 TikZ，不用云图配色。
- **真三维场景**：几何本体就是三维的（带起伏的上下两个界面、厚度/间隙场、相界面推进），或需要多视角并排交代空间关系时，走 pyvista 渲染路线，不要硬用 2D 云图去"假装立体"；渲染配方、三个实测坑与多机位做法见 `references/cfd-3d-render.md`。

**常见错误**：直接从后处理器截图贴进文档（像素 dpi 不够、字体不可控、字号与正文不匹配）；colorbar 渐变带缺 tick；同一张图同时表达两个量；导出图片时带后处理器的白边与 UI 痕迹——一律回原始场数据重画。

2D 云图 / 流线 / 剖面的成图范式与代码见 `references/cfd-figure-patterns.md`；真三维场景（等值面、相界面、多机位、光照与配色）见 `references/cfd-3d-render.md`。3D 图落盘后与 2D 图同一套验收：过 `check_figure.py`，字号与有效分辨率都不打折。

## 八、示意图 / 流程图（双轨）

**判据**：要反复改、给非制图者看（老师/同事会要你改十版）→ **手绘轨**（draw.io、PPT、Illustrator 之类矢量工具）；同构要迭代 ≥5 版、要进版本库、要参数化重出 → **代码轨**（TikZ / matplotlib 的 patch 组合）。

**动笔前先填规格单**：Identity（图号、用途、目标尺寸）/ Purpose（读者看完要得出什么）/ Content（组件表、连线表、分组框）/ Style（语义色、字级、线宽）/ Acceptance（验收项）。组件表和连线表是硬要求——没有它，示意图会变成“画到哪想到哪”。

**七原型**：流程、层级、时间轴、对比、循环、矩阵、地理。先认原型再找参考，比“随手画框”快十倍。

**几条铁律**：同类元素同色、强调色只用一个；箭头方向单一（不要双向箭头混正交箭头）；连线不交叉（交叉就加桥接或重排）；文字不压线（压了就加白底）；对齐用网格，不靠眼估。

**落盘规格与数据图完全同口径**：版心宽、字号 ≥10.5 pt 印刷态、600 dpi PNG 或矢量 PDF/EPS。`references/case-card.md` 的 `kind` 字段已留「示意图 / 流程图」标签，卡片体例通用。

判据、原型图、规格单体例、画法细节、语义色表、验收清单一律见 `references/schematic-and-flowchart.md`。

## 九、图件案例卡体例

看到一张好图（期刊的、别人的、自己以前画的），把它拆成可复用的知识。图不是“学会了就会”，是“见过才想得起来”；但“见过”很容易变成“只记得好看”，案例卡强制你拆到**能复现的程度**。

六段式模板（front-matter 字段 + 正文六段）：

```markdown
---

input: <输入格式，如 long table: group/value>
journal: <出处，或“自绘”>      wow: <1–3>
recipe: <配方脚本路径，或“无”>  preview: <预览图路径>

## 一句话      <≤40 字说清它在讲什么>
## 高级感      <★ 分级 + 一句话说清高级在哪>
## 适用场景    <什么数据、什么论证意图，具体到几组几指标>
```

**分工一句话**：

- `figstyle.py` 是样式的**唯一实现**——`apply_style()`（rcParams 全家桶：字体栈、线宽、刻度、`savefig.dpi`）、`use_size(W)`、`panel()`、`fix_corner_labels()`、`saved_width_in()`、`printed_pt()`、`fit_and_save()`，外加 `_selftest()` 把恒等式逐条钉死。**不要在别的脚本里再抄第二份样式**——样式分叉是这类问题反复复发的根源。

## 十二、这个 skill 的边界（如实说明）

- **不判科学结论对不对**。它管图能不能看清、数据有没有画错（轴范围、单位、误差棒含义、归一化、分幅可比性）；不管你的模型假设、实验设计、统计推断是否成立。**字号达标不等于图好。**
- **`check_figure.py` 只验字号与可选的有效分辨率**：不判配色、不判可读性、不判论证是否成立。`qa-checklist.md` 里“只能人工判断”的那一段，谁也不能替你过。
- **CFD 部分是 Fluent / CFD-Post 这类工具的通用做法**。换 OpenFOAM / COMSOL / ParaView 等其他软件，思路一样、导出方式与后处理命令要自己换；本 skill 不附带任何厂商软件，也不保证某个版本的后处理器导出格式。
- **不接管统计**：n=3 要不要画柱、显著性怎么标，`references/chart-selection.md` 给判据，但统计检验本身不在范围内。
- **不管正文排版**：图注字号、图表编号、题注位置，以及正文口径、项目流程、评审与交付流程，各有专门 skill 或工具负责。**制图只管图；正文口径、项目流程另有专门 skill，别在这里掺。**
- **素材库是参考不是模板**：19 个案例教图型与手法；不许为了“像案例”牺牲字号与分辨率，验收线不变。
- **多栈策略**：正文图一律 matplotlib（可复现、可审计）。plotly / scienceplots 之类可以做交互探索或样式参考，但**成图不得直接进正文**——它们不带本 skill 的字号/版心保证，须在 matplotlib 里按 `figstyle` 重画，或在交付记录里注明例外原因。
