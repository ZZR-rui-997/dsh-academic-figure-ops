# 从 Tavotto 吸收的七条硬规矩（学术插图口径，2026-11-26）

> 来源：开源制图工具 **Tavotto**（AGPL-3.0，v0.21.3）的公开文档，逐份读完后的方法论总结。
> **只借方法论，不抄代码**（AGPL-3.0 的义务不同，直接搬代码会带来许可问题）。
> 与本 skill 的口径冲突处（8 pt 下限 / 150 mm 栏宽）一律以本 skill 的
> **10.5 pt 印刷态判定**与**你自己量出来的正文宽度**为准——它家的数值不进本 skill
> 的判定，只进方法。

## 一、图文件契约（写新图脚本时生效，六条）

Tavotto 把「图文件契约」当作硬约束，违反即视为「死图」（自动化工具接管不了）。
本 skill 不用它的渲染 worker，但把同样六条写成本 skill 新图脚本的写法约定——
满足它，将来任何工具（包括 Tavotto 本身）都能接手这张图：

1. **脚本与产物同目录**，产物文件名写成**静态可解析的字面量**（模块级常量或
   f-string 拼常量都行），不许来自 `sys.argv`、时间戳、随机串或遍历数据目录；
   一图一 stem，一个脚本出多张图用多个 stem。
2. **入口是无参 `main()`**，`if __name__ == "__main__": main()`；**import 期零副作用**
   ——顶层不许跑计算、读大文件、画图。
3. **交付矢量 PDF**（`fig.savefig(OUT / "<Stem>.pdf")`），位图（imshow 的 raster）除外
   且 ≥300 dpi；不拿 300 dpi 的 PNG 当交付物。
4. **可复现**：随机种子固定（`np.random.default_rng(<固定数>)`）；**禁 `plt.show()`**
   ——它会阻塞无人值守渲染。「先弹窗看效果」只适用于人工预览环节，
   落盘脚本一律走 `show_or_save` 逻辑（弹窗仅人工模式）。
5. **新脚本只用 matplotlib 画图**，不弹窗不等输入（tkinter/Qt 对话框、`input()`、
   argparse 必填参数都禁）。
6. **非 matplotlib 栈的原有脚本不改原文件**——在旁边另写 `<原名>_matplotlib.py`
   复现其图（数据计算可保留原栈，绘图换 matplotlib）。

> 现状差距：一部分既有图脚本是顶层直接跑，不满足第 2 条——**存量不强制改造**，
> 新写的图脚本按此执行；改造存量留到图件批量返工时顺路做。

## 二、preflight 四级发现（导出/验收前的人工判断框）

Tavotto 导出前的检查结果分四级、且**永不锁导出，未决项写进随附报告**。
本 skill 的 `check_figure.py` 只有「过 / 不过」两态，人工判读时按它的四级来组织话术：

| 级 | 含义 | 本 skill 对应 |
|---|---|---|
| **to fix** | 必改，不改过不了审 | 字号 / 分辨率 FAIL（机器判） |
| **to review** | 疑似问题，需人确认 | `anti-patterns.md` 的人工项 |
| **not verifiable** | 机器根本查不了（如位图内文字） | `qa-checklist.md` 的 B 类 |
| **suggestion** | 只是建议 | 风格建议（如配色微调） |

规矩：**任何一级都不锁交付，但 to-fix 与 not-verifiable 必须写进交付说明**，
不能「看起来还行就交」。

## 三、克制原则（强化版，比 anti-patterns 更进一步）

Tavotto 的表述更硬：**数据之外的效果，一个都不擅自加**。背景色块标注「这段好」、
箭头指数据点、「peak here」式文字、高亮/阴影/星号显著性装饰——没有作者明确要求
一律不加；你觉得确实能帮读者理解，**先问**（加什么、为什么），点头才画。
「先加上再让人删」不是省事，是把别人的图改成了自己的图。

与 `anti-patterns.md` 的分工：那边列「什么丑」，这边立「什么不许擅自加」。

## 四、多子图规范（比 cfd-figure-patterns 更严的补充四条）

1. **绝不用 matplotlib 之外的东西拼图**——不用 PIL/ImageMagick 拼位图、不用
   LaTeX subfigure、不导散件让人自己拼；非矢量整图既毁验收，也接不了自动化工具。
2. **每个子图的 x/y 轴标题各自标全**——同行子图哪怕 y 轴标题一字不差也逐个
   `set_ylabel`，不许只给最左/最下的留、其余留白。
3. **不 `sharex/sharey`**——它会把里侧子图的刻度标签藏掉；要对齐范围就逐个
   `set_xlim/set_ylim`，刻度与轴标题每个子图自己来。
4. **子图标题「各归各位」**：`ax.set_title()` 默认居中落在自己子图正上方，
   不挤整图左上角、不 `loc="left"`（作者点名要左对齐时才左对齐）。

（注：本 skill `panel()` 的分幅标号放在坐标区下方，是常见的期刊图惯例，与此不冲突——
它约束的是 `set_title`，`panel()` 管的是分幅标号。）

## 五、字重策略：只有轴标题加粗（按角色，不整图一刀切）

`text_weight_policy`：figure/title/ticklabel/legend_text/annotation 一律 normal，
**只有 axis_label 用 bold**；文档里明言「绝不整图一刀切加粗」。本 skill 现行：
`panel()` 分幅标号用 bold（结构标号，不是正文题注）+ 其余 normal——与此兼容，
**再补一条**：轴题（如 `x / mm` 这类）默认 `fontweight="bold"`，题注类文字不加粗。

## 六、保留式规范化的「禁止绕路」清单（修旧图时的纪律）

修一批历史图（例如数十张 CFD 云图与早期试算图），无论走「按 `figstyle` 重画」
还是外部工具（如 Tavotto 本体），下面六条绕路一律禁止——它们产出的是
「看起来改了」的假修复：

1. 不缩放位图冒充「已改字号」（像素放大的字不是矢量字，期刊拒收）；
2. 不整份替换 SVG/PDF 蒙混验收；
3. 不套全局 rcParams 主题（会连数据外元素一起改）；
4. 不为「消除拥挤」删曲线 / 删图例项 / 删刻度 / 截断文字；
5. 不改配色 / 数据 / 坐标范围 / 子图结构——那些是「重做」，不是「规范化」；
6. 工具报 `font_unavailable`（机器没那个字体）就装字体或换字体并如实报告，
   不自己换相近字体宣称达标。

## 七、期刊规范体例（resolution-and-format 的升级方向）

Tavotto v2 期刊目录的每条事实都带六个字段：**图类条件、投稿阶段（修稿 / 录用后 /
生产不可互换）、比较符（≥ / ≤ / in / not_in）、要求强度（must / preferred /
permitted）、来源原文、`coverage.result=not_stated`（≠ 未规定）**。
本 skill `resolution-and-format.md` 目前是「三类图 × 五家出版社」一张表；
下次扩表时按这套字段来，尤其：

- 每个数值必须带出处（官网 URL / 抓取日期）——本 skill 已有惯例，坚持；
- 「未见规定」与「未规定」分开写；
- preferred 与 permitted 分开（preferred 不是白名单）。

## 八、口径对表（防混用）

| 项 | Tavotto 默认 | 本 skill | 谁赢 |
|---|---|---|---|
| 字号下限 | 8 pt（最终有效） | 10.5 pt ±5%（印刷 pt） | **本 skill**（它的 preflight 会放过 9 pt 的图，这边不会） |
| 双栏宽 | 150 mm | 你自己量出的正文宽度（示例值 146.5 mm，即 14.65 cm） | **本 skill**（用它的 override 表达，别改默认值） |
| 线宽 | 0.5 / 0.75 / 1.0 / 1.5 四档 | 未定死，随图 | 参考 |
| 色系 | Scientific colour maps（batlow / roma） | Okabe-Ito + 自定义 INK/CMAP 系 | **本 skill**（论文已在用）；禁 jet / rainbow 这条两边一致 |
| 轴标题 | `Title (unit)` + bold | `量 / 单位` 斜线式 + normal | **本 skill**（中文出版物习惯），bold 见第五条 |
