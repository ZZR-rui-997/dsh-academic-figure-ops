# 审丑清单：看到就改

> 这张表的用法是**反向**的：不是"这样做更好"，而是**"看到这个就是错的"**。
> 每一条都是真实项目或公认实践里出现过的典型问题。

## 一、一眼就掉档的问题（严重度 ★★★）

### 1. 字号偏小

**症状**：图上看着还行，插进 Word 缩到正文宽度（示例 14.65 cm，A4 + 左右 3.17 cm 页边距的常见值）后，轴标签要凑近看。

**判据**：印刷 pt < 9.5 即不合格（常用基线 10.5 pt）。
用 `check_figure.py` 量，**不要用肉眼**。

**实例**：一批 22 张 CFD 云图实测 4.84–7.49 pt，只有同一文档里已定稿那组图的 57%。

### 2. 分幅比较时轴范围不一致

**症状**：2×3 小多图，每个分幅各自 autoscale，看起来"变化幅度差不多"。

**为什么致命**：这等于**用布局制造不存在的对比**。
一个变化 5% 的分幅和一个变化 500% 的分幅，视觉上完全一样。

**修法**：显式 `set_xlim` / `set_ylim`，或在循环外先算全局范围。

### 3. 云图 colorbar 各自归一化

**症状**：多时刻 VOF 云图，每张的颜色都是"从蓝到红"。

**为什么致命**：读者会以为该组分的量一直很多，实际是每张都重新拉伸了。

**修法**：`vmin=0, vmax=1` 固定，或共用同一个 `ScalarMappable`。

### 4. y 轴不从 0 起，且没标注

**症状**：柱状图 y 轴从 0.70 开始，两组 0.83 vs 0.88 看起来差 5 倍。

**判据**：柱状图**必须**从 0 起（柱高是绝对量）。
折线图可不在 0 起，但要么在图注说明"纵轴为放大显示"，
要么加**断轴标记**。

**实例**：调研时看到的一张基准对比图，y 轴截断在 0.70，
"Ours 0.93 / Baseline 0.83" 看起来差一档，实际差 12%。

### 5. 用灰度深浅区分系列

**症状**：5 条线全是不同深浅的灰。

**为什么致命**：黑白打印会全糊。通用做法是明确规定：
**系列区分用颜色 + 记号形状，不用灰度深浅**。

## 二、让人怀疑专业度的问题（严重度 ★★）

### 6. 中文变方框

**症状**：图里出现 `□□□□`。

**根因**：`font.family` 没设 SimSun，或在 `$...$` mathtext 里写中文。
`figstyle.apply_style()` 已处理前者；后者要改写法：

```python
✅ ax.set_xlabel('沿程距离 $x$ / mm')
❌ ax.set_xlabel(r'$沿程距离 x / mm$')     # math mode 里中文 → 方框
```

### 7. 单位用方括号

**症状**：`速度 [m/s]`、`压力 [kPa]`。

**改**：`速度 / (m·s⁻¹)`、`压力 / kPa`。斜线，不用方括号。

### 8. 图例压住数据

**症状**：`legend(loc='best')` 自己找的位置，正好盖住最密的数据点。

**改**：显式给 `loc`（`'upper left'` 等），或放到坐标区外
（`bbox_to_anchor=(1.02, 1)`），或直接**在线末端标注**代替图例。

### 9. 文字压住线条，且没有白底

**症状**：注释文字直接叠在曲线上，两样都看不清。

**改**：`bbox=dict(facecolor='white', edgecolor='none', pad=1.5)`，
或加 `path_effects` 白色描边。

### 10. 网格线过密

**症状**：满屏浅灰网格。

**推荐做法**：**不用 grid**。坐标轴线 + 刻度已经够读。
若确实需要（读具体数值），只开主刻度网格，浅灰 `alpha=0.3`。

### 11. 双 y 轴

**症状**：左右两个 y 轴，颜色不同，图例要写两遍。

**为什么不好**：两条曲线的交叉点**没有任何物理意义**，
但读者会去解读它。这是图表欺骗的经典形式。

**改**：拆成上下两个分幅，共享 x 轴。

### 11b. 角上两个刻度标签叠在一起（左下角最常见）

**症状**：y 轴最小值的 `0.00` 与 x 轴最小值的 `0.0` 挤在同一个方块里，
数字互相穿模。放大看是两段文字叠印。

**为什么发生**：这两个标签分别在左外边距与下边距里排版，
但"角上那块"被两边同时占用；`constrained_layout` 与 `tight_layout` 都不处理角部交叉。
只要 y 轴和 x 轴的最小值都带小数（`0.00` / `0.0`），就必然撞上。

**改**：调 `fs.fix_corner_labels(ax)`——它把 y 轴极值标签改成"只向内长"
（最小值 `va="bottom"`、最大值 `va="top"`），于是不再向下越过轴线。
只改对齐、不改刻度值，四边轴线与刻度朝内都不受影响。

**判据**：把图缩到正文宽度看一眼角部；数字能分开读才算过。

### 11c. 分幅标号 (a)(b)(c) 悬空或压字

**症状**：两种都算错——标号离它上方的坐标区太远（悬在行间、像属于下一行），
或者贴太近把 `x / mm` 压住。

**为什么发生**：标号的正确位置取决于"该坐标区下方还有多高的东西"
（有 x 轴名？有刻度数字？共享轴时上一行没有刻度数字）。任何**固定偏移**
（按坐标区高度的比例 `dy=-0.28`、按固定 32 pt）都会在某种布局下算错。
实测：`dy=-0.28` 在 13×8.1 in 的六分幅里偏出 **21 mm**；
换成固定 32 pt 后 `(d)(e)(f)` 直接压在 `x / mm` 上。

**改**：调 `fs.panel(ax, "(a)")`——它会先 `fig.canvas.draw()` 实测 x 轴名与
刻度数字实际占到哪里，再把标号放在其下 6 pt。因此必须在 `set_xlabel` /
`set_title` 都调完、紧接 `savefig` 之前调用；顺序反了会量到空布局。

**判据**：标号与上方坐标区、下方轴名之间都有肉眼可见的空白，且不与其他行相撞。

## 三、显得不整齐的问题（严重度 ★）

### 12. 同一批图字体不一致

**症状**：一张图 Times+宋体，下一张 SimHei。

**实例**：同一批图里，一部分脚本用 SimHei/YaHei，
其余用 Times+SimSun。

**改**：全部走 `figstyle.apply_style()`。

### 13. dpi 五花八门

**症状**：同一批图 150/170/180/300/400 dpi 混着来。

**改**：统一 300（`DEFAULT_DPI`）。

### 14. 轴线宽不统一

**症状**：这张 0.8，那张 0.65K。

**改**：`apply_style()` 统一设 `0.65 × K`。

### 15. marker 密到糊成一条粗线

**症状**：折线图上每个数据点都画 marker。

**改**：`markevery=5`（或按点数算）。

### 16. 图例有边框、圆角、阴影

**改**：`frameon=False`，或 `edgecolor='black', fancybox=False`。
推荐后者（保留细黑框，无圆角）。

## 四、内容层面的假象（严重度 ★★★，最危险）

### 17. n=3 画纯均值柱

**症状**：三根柱子，高度不同，看起来有趋势。

**真相**：3 个点完全可能 [1,1,9] 和 [4,5,3] 均值相同。
**必须叠散点**（见 `chart-selection.md` §三）。

### 18. n=3 标显著性星号

**症状**：`*`、`**`、`***` 标在 3 个样本上。

**问题**：n=3 的检验没有统计意义。**别标**。

### 19. 误差棒不写是什么

**症状**：有误差棒，但图注没说 ±SD 还是 ±SEM。

**问题**：SEM 比 SD 小 √n 倍（n=9 时小 3 倍）。
不说明 = 读者无法判断，且**故意选小的那个**可视为误导。

### 20. 用平滑曲线连接离散点

**症状**：5 个数据点，画成一条光滑的样条曲线。

**问题**：曲线在数据点之间的形状**是编出来的**。
除非有物理模型支撑（且说明），否则用直线连接。

### 21. 只画"最好看"的那一条

**症状**：多个工况，只展示了效果最明显的一个。

**问题**：选择性展示 = 选择性报告。要么全给，要么说明筛选标准。

### 22. 图注夸大结论

**症状**：图注写"该组分显著向深部扩散"，图上只是颜色深一点。

**判据**：图注只描述**图上能看到的**，结论放正文。

## 五、快速自检：把图缩小到正文宽度看一眼

最有效的单一步骤：**把图缩到实际印刷尺寸，然后退后一步看**。

```powershell
# 生成一张 553 px 宽的预览（≈正文宽 14.65 cm 时 @96dpi）
python -c "from PIL import Image; im=Image.open('fig.png'); w,h=im.size; im.resize((553, int(h*553/w)), Image.LANCZOS).save('preview.png')"
```

或者直接在 Word 里插进去看——**这才是最终呈现**。

## 六、判断优先级

问题很多时按这个顺序修：

1. **字号**（决定能不能读）→ 2. **轴范围一致性**（决定结论真假）
→ 3. **colorbar 归一化**（同上）→ 4. **遮挡/重叠**（决定读得顺不顺）
→ 5. **配色统一**（决定这一批图看起来是不是一套）
→ 6. 其余。

**不要**先调配色再调字号——字号不合格时，配色再美也没用。
