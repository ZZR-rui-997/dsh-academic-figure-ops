> 本文件的每个数字都有出处。**未标出处的数字不许进论文，也不许当验收基准。**

## 一、反算链（这是整个体系的地基）

### 1. 正文宽度从哪来

先量你自己的页面正文宽度：Word 里看页面设置（或把 docx 解压后读 `word/document.xml` 里的
`w:pgSz` / `w:pgMar`），再用下式换算。

以一份 A4 单栏版式的文档为例，`pgSz w=11906` twips、`pgMar left=1800 right=1800` twips
（左右各 3.17 cm）：

```
正文宽 twips = 11906 - 1800 - 1800 = 8306 twips
正文宽 cm    = 8306 / 1440 * 2.54 = 14.65 cm
正文宽 in    = 14.65 / 2.54      = 5.767716535433071 in
（精确值 = 8306/1440*2.54 = 14.650861 cm = 5.768056 in；本规程一律用
取整的 14.65 → 5.7677 in，偏低 0.0059%。实测它对字号判定的
影响 < 0.001 pt，可忽略，但引用时要知道这个取整。）
```

**⚠ 曾经算错过一次**：把 `8306 twips` 当成了 `163.50 cm`（忘记 /1440*2.54）。
单位换算是这类反算链最常见的翻车点。

**把 14.65 当成示例值，不是常量**：换成你自己的正文宽度后，下面整条反算链照样成立。
凡是引用正文宽度，要么写具体值（如 `14.65 cm` / `5.7677 in`），要么写"你的正文宽度"，
不许写"16 cm 左右"这种约数。

### 2. 字号为什么要放大

matplotlib 的 `font.size` 单位是 pt，但它是**相对画布**的：
一个 10.5 pt 的字，占画布高度的比例是固定的。画布越宽，字相对越小。

把画布从 `W` 英寸缩放到正文宽度 `TW` 英寸时，缩放因子是 `TW / W`，
所以字也等比缩：`印刷pt = 设定pt × TW / W`。

**反过来推**：若希望印刷恰为 10.5 pt，则设定 pt 必须是

```
设定pt = 10.5 × W / TW = 10.5 × K,   其中 K = W / TW
```

这就是 `use_size(W)` 的全部内容。**是恒等式，不是经验系数。**
`TW` 默认取 5.7677 in（即 14.65 cm 的示例值），可被 `set_text_width_cm(...)`
或模块级 `TEXT_WIDTH_CM` 覆盖；改了 `TW`，`K` 自动跟着变。

### 3. 落盘后怎么量

落盘 PNG 有两个数：像素宽 `px`、dpi。实际画布宽 `saved_w_in = px / dpi`。

因为 `bbox_inches='tight'` 会裁掉空白，`saved_w_in` 通常 **略小于** figsize 宽。
实测一组 10 张已定稿图的 `saved_w_in / figsize_w` 比值：

| 图 | figsize 宽 in | 落盘宽 in | 比值 |
|---|---|---|---|
| 图 1 | 13.0 | 13.1133 | 1.009 |
| 图 2 | 12.6 | 12.0967 | 0.960 |
| 图 3 | 11.6 | 11.7267 | 1.011 |
| 图 4 | 12.6 | 12.1033 | 0.961 |
| 图 5 | 11.8 | 11.3033 | 0.958 |
| 图 6 | 12.8 | 12.6333 | 0.987 |
| 图 7 | 13.0 | 13.02 | 1.002 |
| 图 8 | 13.2 | 12.8467 | 0.973 |
| 图 9 | 14.5 | 14.6133 | 1.008 |
| 图 10 | 10.3（预期） | 10.29 | 0.999 |

**结论：9/10 落在 0.96–1.01，即 ±4% 内。**
`bbox_inches='tight'` 不是"普遍缩小 20–40%"。唯一例外是三维图：
一张图按 `use_size(10.3)` 设基准，但 `figsize` 宽写成 13.5 in，落盘只有 10.29 in
（**76%**）——因为三维投影区的空白被裁掉了。
⇒ **凡三维图，必须实测算宽度再定基准，不许照 figsize 推。**

> 常见误传：旧笔记里写"实际宽度常比 figsize 小 20–40%"。这句话与本表矛盾，
> 正确写法是"一般 ±4%，三维图可低至 76%"。本文件的口径以本表为准。

### 4. 完整反算（一次跑通）

```python
# 有落盘文件时（TW_IN = 正文宽度英寸数，示例 5.767716535433071）
saved_w_in = px / dpi
printed_pt = set_pt * TW_IN / saved_w_in

# set_pt 怎么取，看写法：
#   口径① use_size(W) → set_pt = 10.5 * W / TW_IN
#   口径② 固定字号    → set_pt = 10.5
```

`check_figure.py` 就是这段的封装。别自己再写一遍，容易漏掉口径。

## 二、固定样式表

来源是一套自用绘图模板里 `use_size` / `apply_style` 的原始实现；
`figstyle.py` 是它的合并与去重，**数值逐项对齐**。

| 项 | 值 | 说明 |
|---|---|---|
| 正文宽度 | 参数化；示例 14.65 cm = 5.7677 in | 见 §一.1，务必换成你自己的值 |
| 轴标签字号 | 印刷 **10.5 pt**（`TARGET_LABEL_PT`） | `axes.labelsize` |
| 刻度字号 | 印刷 **9.5 pt**（`TARGET_TICK_PT`） | `xtick.labelsize` / `ytick.labelsize` |
| 图内其他文字 | 印刷 10.5 pt 基准 | `font.size` |
| 落盘 dpi | **300**（`DEFAULT_DPI`） | `savefig.dpi` |
| 英文字体 | **Times New Roman** | `font.family` 第一位 |
| 中文字体 | **SimSun**（宋体） | `font.family` 第二位；**西文必须在前** |
| 轴线 | 四边纯黑实线 | `axes.edgecolor='black'`，四边都可见 |
| 轴线宽 | `0.65 × K` | `axes.linewidth` |
| 刻度方向 | **朝内** | `xtick.direction='in'` / `ytick.direction='in'` |
| 刻度宽（主） | `0.65 × K` | `xtick.major.width` |
| 刻度长（主） | `3.0 × K` | `xtick.major.size` |
| 刻度宽（次） | `0.55 × K` | `xtick.minor.width` |
| 刻度长（次） | `1.7 × K` | `xtick.minor.size` |
| 上/右刻度 | **都开** | `xtick.top=True` / `ytick.right=True` |
| 图例边框 | 黑边、无圆角 | `legend.edgecolor='black'`、`legend.fancybox=False` |
| 网格线 | **无** | 通用做法是不用 grid |
| 图注 | 写在 **Word 里图的下方**，不进图 | 图内不画图注文字 |
| 分幅标号 | `(a)(b)(c)`，画在**坐标区下方** | `figstyle.panel(ax, "(a)")` |

### 单位写法

```
✅  速度 / (m·s⁻¹)      x / mm        t / s
❌  速度 (m/s)          [mm]          Time(s)
```

**用斜线，不用方括号**；量符号与单位之间留空格；英文量与中文量都按此。

## 三、配色

出处：同一套绘图模板里的 `INK` / `CMAP_AP` 定义；Okabe–Ito 为公认色盲友好八色中的五色。

```python
INK      = '#153A60'   # 主墨色（深蓝），用于主曲线/主系列
GREY     = '#333333'   # 次要文字/辅助线
OKABE_ITO = ['#0072B2',  # 蓝
             '#E69F00',  # 橙
             '#009E73',  # 绿
             '#D55E00',  # 朱红
             '#CC79A7']  # 紫红
INK_SEQ  = 五档深蓝递进    # 顺序型数据（单变量递增）
CMAP_AP  = 蓝白红低饱和双向 # 发散型数据（有正负/有中间参考）
```

### 选色规则

1. **系列区分：颜色 + 记号形状（marker）+ 线型**，三者至少用两个。
   **禁止只用灰度深浅区分系列**——黑白打印会糊在一起。
2. **数量与语义匹配**：
   - 类别（无顺序）→ `OKABE_ITO` 按序取；
   - 顺序（如 5 个 H 值）→ `INK_SEQ` 或 matplotlib 顺序 cmap（`viridis`）；
   - 发散（有 0 / 有参考值）→ `CMAP_AP`（蓝白红），**必须对称且 0 在中点**。
3. **禁止**：`jet`、`rainbow`、`RdYlBu_r` 当类别色用（实际项目里常见多套色标混用，视觉不统一）。

> 常见现状：同一批 CFD 脚本里并行用过 5 套具名色标（`RdYlBu_r`、`viridis`、`magma`、`cividis`、`RdBu_r`），
> 同一个汇报里并排看很花。**统一到 `CMAP_AP`（速度/压力场）+ `INK_SEQ`（浓度/龄期场）即可**，
> 不必逐个脚本改，成图时统一走 `figstyle` 即可。

## 四、几何与留白

| 项 | 建议值 | 理由 |
|---|---|---|
| 单栏图 figsize 宽 | **12–14.5 in** | ⚠ 不是 5.77 in！画布大才既够字号又够分辨率，见 resolution-and-format.md |
| 通栏图 | 同上 | 多数中文论文用通栏，没有真单栏 |
| 高度 | 按内容，1.8–3.0 in 常见 | 纵横比 2:1 – 3:1 的宽图最省版面 |
| `layout` | `'constrained'` 优先 | 比 `tight_layout` 稳，配合 `bbox_inches='tight'` |
| 分幅间距 | 由 constrained 自动 | 手调 `wspace/hspace` 只在 constrained 失效时用 |
| 分幅标号位置 | 坐标区**下方、实测避开 x 轴名**（`figstyle.panel`，v3 实测式） | 见 `figstyle.panel` docstring 里两版失败记录 |
| 边距 | `bbox_inches='tight'`，`pad_inches` 默认 | 不留大空白，Word 里再调 |

### 三维图的特殊处理

- 单栏 7 cm 的三维图**会挤字**——这是既有教训，别做；
- 三维图 `tight` 裁切比例不稳（可低到 76%），要么用 `fit_and_save` 迭代，
  要么**实测算出落盘宽后**手动定 figsize；
- `use_size(W)` 里的 `W` 应填**预期落盘宽**，不是 figsize 宽。

## 五、验收阈值

| 场景 | 容差 | 参数 |
|---|---|---|
| 批量体检（与已定稿那组实测带一致） | **±5%** | `--tol 0.05`（默认） |
| 单图自检 / 交付前 | **±2%** | `--tol 0.02` 或 `fit_and_save(tol=0.02)` |

一组 10 张已定稿图的实测分布：均值 10.65 pt，范围 **10.39–10.96**，最大偏差 4.4%。
所以 ±5% 是**既有实绩的自然包络**，不是拍脑袋定的。
