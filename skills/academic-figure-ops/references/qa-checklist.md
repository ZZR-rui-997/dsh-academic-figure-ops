# 落盘前核验清单

> 用法：每张图落盘后，从上往下过一遍，**能勾上的才是过了**。
> 前 6 项可以脚本验（`check_figure.py` + 肉眼），后 6 项只能人工判断。
>
> **编号说明**：本文件的检查项编作 **C1–C6 / D1–D6**（C = 机械可验，D = 人工判断）；
> 其后三节是整体性检查，用**章节字母** E（交付前 3 问）/ F（Word 最终检查）/ G（假过关表），
> 不再细分编号。不要和规程自身的验收标准 A1–A8 混用——那 8 条是"这套规程本身做得对不对"，
> 本文件是"每一张图出得对不对"，两套编号刻意分开。

## C. 可机械核验的（6 项）

- [ ] **C1 字号达标**：`python check_figure.py --fs 10.5 <png>` 或 `--canvas-w W`，退出码 0。
      实测印刷字号在 10.5 ±5% 内（单图交付用 ±2%）。
- [ ] **C2 导出 dpi = 300**：`check_figure.py` 输出的 dpi 列是 300。
- [ ] **C3 有效分辨率达标**：有效 dpi ≥600 线条图 / ≥300 照片
      （`check_figure.py --min-eff-dpi 600` 判）。
      有效 dpi = 落盘像素宽 ÷ 正文宽度英寸数（示例 5.7677）；900 px 宽只有 156 dpi，不要被 `dpi=300` 骗了。
      超过 2 倍说明画布开太大，字号必然被压。
- [ ] **C4 文件格式**：`.png`（用于 Word）；需要矢量时另存 `.pdf`。
      **不接受** `.jpg`（有损，等值线会出虫）。
- [ ] **C5 无机器绝对路径**：脚本里不出现盘符绝对路径（Windows 下 `盘符:` + 反斜杠开头的写法）硬编码
      （数据路径应通过参数/配置传入，否则换机器就跑不了）。
- [ ] **C6 脚本可重跑**：随机数带 `seed`；数据来源是文件而非硬编码数组；
      重跑出来的图**逐像素一致**（或图注说明"示意数据"）。

## D. 只能人工判断的（6 项）

- [ ] **D1 字号真的够大**：把图缩到正文宽度（示例 14.65 cm；屏幕上约 553 px @96dpi）看一眼，
      轴标签读得出来吗？colorbar 的 ticks 读得出来吗？
      **不要靠放大 400% 判断**——那是自欺。
- [ ] **D2 没有遮挡**：
  - 图例压住数据点？
  - 文字压住线条/点（且没有白底 `bbox`）？
  - 分幅标号压住轴标签？
  - colorbar 的 label 压住 tick 数字？
- [ ] **D3 没有重叠文字**：两条轴的标签相撞（共享轴没关）、
  图例项之间挤在一起、注记文字互相覆盖。
- [ ] **D4 轴范围没被截断**：y 轴起点不是 0 时，
  要么明确是放大（图注说明），要么就是错的（视觉夸大差异）。
  **断轴必须标出来**（`//` 符号）。
- [ ] **D5 单位与量符号**：斜线写法 `x / mm`；量斜体 `$x$`、单位正体；
  中文量的单位也用斜线；**没有方括号** `[mm]`。
- [ ] **D6 图能自明**：把图单独拿走（不看正文），能说出"这是在比什么"吗？
  需要图注写 5 行才能说清 → 重画，不是加图注。

## E. 交付前最后 3 问

1. **这张图支撑正文哪一句结论？** 指不出来 → 图是多余的。
2. **如果数据反了，这张图会变什么样？** 变不出明显区别 → 图没有鉴别力。
3. **评委可能问什么？** 图上有答案吗？（如 n 是多少、误差棒是什么、单位是什么）

## F. Word 里的最终检查（出图后，插进论文前）

- [ ] 图宽设为**正文宽度**（示例 14.65 cm；不是"适应页面"，不是随手写的 16 cm）；
- [ ] 图注在图的**下方**，字号按校方规范（通常五号/10.5 pt）；
- [ ] 图注含：图号、图题、必要的说明（n、误差棒含义、色标含义）；
- [ ] 正文里有 `如图 1-1 所示` 的**交叉引用**（不是手打图号）；
- [ ] 所有分幅都被正文提到（`(a)` 讲什么、`(b)` 讲什么）；
- [ ] 图号连续无跳号，与目录/图表清单一致。

## G. 常见"看起来过了其实没过"

| 假过关 | 真相 |
|---|---|
| 在 400% 缩放下看得清 | 印出来是 100%，必须按 100% 判断 |
| `check_figure.py` 退 0 就是好图 | 它只验字号与（可选的）有效分辨率。配色/遮挡/论证都不管 |
| 和已定稿那组"看着差不多" | 要量数字。那组实测 10.39–10.96 pt，差 0.5 pt 就降一档 |
| dpi 400 更清楚 | 正文宽度固定，400 dpi 只是文件更大；300 够印刷 |
| 图例自动放最好 | matplotlib 的 `best` 常放在数据最密处，**几乎总要看一眼再改** |
| 误差棒画了就行 | 是 SD / SEM / 极差 / 95%CI，必须写明，否则读者无法判断 |

## H. 示意图 / 流程图的验收（非数据图专用）

> 数据图用 C/D/E/F/G；技术路线图、流程/装置/机制示意、文献定位图走本节。
> 完整规程（判据、七原型、规格单、画法铁律、语义色表）见
> `schematic-and-flowchart.md`；此处只列验收线。

- [ ] **H1 有规格单**：动笔前 `figure_spec_<id>.md` 已填（claim/组件表/连线表/分组/流向/强调组件）。
- [ ] **H2 落盘规格与数据图同口径**：正文宽度（示例 14.65 cm）；字号 ≥10.5 pt 印刷态（缩到 14.65 cm 宽实看）；
      600 dpi PNG 或矢量 PDF/EPS；白底；无 JPG。
- [ ] **H3 语义色出自语义表**：深描边+浅填充；"本文贡献"组件有加粗描边+暖色强调；
      同名组件全论文标签逐字一致；蓝=本方法的语义全论文不漂移。
- [ ] **H4 图在论证不是陈列**：去掉文字后结构仍传达概念；多概念图用了不同视觉模式；
      无"五个等大方框"式排版；容器内文字占比 <30%。
- [ ] **H5 有证据件**：装置/流程图标注实测参数（工况、判据、量值），不是空标签框；
      数字出处写进交付卡/规格单，标明每个数值的来源（实测记录或计算式）。
- [ ] **H6 渲染 9 类缺陷 = 0**：文字裁切/重叠/箭头穿件/落错/悬空/间距不均/留白失衡/字太小/构图偏侧。
- [ ] **H7 灰度可读**：转灰度后语义仍可辨。
- [ ] **H8 可复现声明**：交付卡记轨道（A 手绘 / B TikZ）与源文件路径（.drawio/.pptx/.tex），
      他人可重开重导；AI 2023 修饰过要注明；AI 生图一律不进正文。
